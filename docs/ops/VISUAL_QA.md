# Private UI visual QA

Канонический visual-QA проход приватного интерфейса выполняется Playwright-тестом `tests/e2e/visual-baseline.spec.ts` после production build и наполнения test DB.

## Матрица

| Ширина | Сценарий |
|---:|---|
| 375 | мобильная навигация, карточки вместо рабочих таблиц, отсутствие page overflow |
| 768 | переходный layout и доступность основных действий |
| 1280 | рабочая плотность, таблицы, sidebar и фильтры |
| 1440 | широкая компоновка без избыточного растяжения контента |

Критические экраны: `/dashboard/`, `/analyst/`, `/admin/projects/`, `/tools/research/`, `/demo/`. Для каждого запуска Playwright прикладывает PNG с именем `<screen>-<width>` к test result.

## Review checklist

- нет горизонтальной прокрутки всей страницы;
- заголовок, основной рабочий объект и primary action видны в ожидаемом порядке;
- таблица на desktop и карточки на mobile не теряют ключевые данные;
- focus, drawer/dialog и touch targets сохраняют доступность;
- статусы читаются текстом, цвет используется только как дополнительный сигнал;
- отсутствуют публичные `ch-*` tokens и случайные цвета в private UI.

PNG — диагностический артефакт конкретного запуска, а не бессрочный pixel-perfect эталон. При осознанном изменении структуры сначала обновляется этот документ и тестовая матрица, затем выполняется новый проход на всех четырёх ширинах.
